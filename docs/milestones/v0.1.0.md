# v0.1.0 — Personal-use MVP

## Goal

Provide a small NotiRelay build that can run as a personal Windows 11 utility,
capture newly arriving notifications from explicitly enabled Source
Applications, and relay them directly to one locally configured Bark destination.

## Acceptance Scenario

Given NotiRelay has notification access, an enabled Source Application, and a
valid Bark Destination Profile, when that Source Application creates a new
Windows notification, NotiRelay relays it to Bark once and exposes a clear local
success or failure state while remaining available from the notification area.

## In Scope

- Windows notification-listener permission
- Startup baseline and session deduplication
- Captured Notification normalization
- Source Application discovery and explicit allowlist
- One Bark Destination Adapter and Destination Profile
- Direct best-effort Bark delivery
- Local non-secret configuration
- Secure local credential storage
- Notification-area lifecycle, hide-on-close, activation, and explicit exit
- Basic local operational and error status

## Out of Scope

- SQLite Outbox and durable retry
- Delivery recovery after application exit or crash
- Telegram and Generic Webhook
- Advanced keyword Filters and configurable Routes
- Full Activity history or retained notification-content search
- Import, export, backup, and cloud telemetry
- Store/WinGet public release and official ARM64 support

## Delivery Semantics

The MVP uses best-effort direct delivery. A failed request may be reported during
the current session, but it is not durably queued and will not resume after an
application restart. Durable at-least-once delivery is planned for v0.2.0.
