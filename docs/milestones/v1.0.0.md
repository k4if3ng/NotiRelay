# v1.0.0 — First Stable Release

## Goal

Produce a small publish-ready Windows 11 notification relay with durable
at-least-once delivery to Bark, Generic Webhook, and Telegram.

## Acceptance Scenario

Given notification access, an enabled Source Application, a matching keyword
Filter, and at least one valid Destination Profile, a newly arriving Windows
notification is durably queued, delivered to every configured destination, and
reported in bounded operational statistics. A transient failure is retried after
restart without blocking later Deliveries.

## Delivery Semantics

Delivery is at least once. NotiRelay persists each per-destination Delivery before
dispatch. Pending, retry-scheduled, and expired active Deliveries are eligible for
dispatch. Retries use bounded exponential delays and do not impose strict global
ordering. A crash after remote acceptance but before local acknowledgement can
produce a duplicate.

## Release Boundary

The supported runtime target is Windows 11 x64. ARM64 is compilation-only until a
physical ARM64 device is validated. Store identity, signing, listing text, and the
Store-backed WinGet identifier must be replaced with values from the publisher's
Partner Center reservation during actual submission.
